# 柏总管 · 微信小程序（uni-app + Vue 3）

C 端小程序。当前完成 **首页（我的项目）**、**项目详情页**、**工程动态页**、**记账页**、
**验收页**、**验收详情页**、**登录页**、**角色说明页** 与 **我的（个人中心）** 的
1:1 还原，并接通微信登录、手机号绑定、我的项目、搜索筛选、项目邀请确认、无项目引导、
跨项目验收收件箱、验收详情、业主签名、记账总览 / 流水 / 对账、消息中心、订阅状态、
意见反馈与注销账号；另新增 **租户管理员移动管理端** 与 **考察计划 / 路线规划**。
进度汇报提交页是下一批页面。

## 运行

### 方式一：HBuilderX

1. 用 HBuilderX 打开 `miniapp/` 目录；
2. 运行 → 运行到小程序模拟器 → 微信开发者工具；
3. 微信开发者工具需要在「详情 → 本地设置」勾选
   **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**。

### 方式二：CLI

```bash
cd miniapp
npm install
npm run dev:mp-weixin   # 产物在 dist/dev/mp-weixin，用微信开发者工具导入
npm run dev:h5          # H5 预览（登录会走 mock code）
```

## 后端地址

`src/config.js` 默认 `http://127.0.0.1:3000/api/v1`。真机调试请改成局域网 IP，
或用环境变量：

```bash
VITE_API_BASE=http://192.168.1.20:3000/api/v1 npm run dev:mp-weixin
```

生产环境必须是已在小程序后台配置的 HTTPS 域名。

## 登录流程

后端 C 端身份是**微信 openid**，没有短信验证码登录接口。因此：

- 登录页的「登录 / 微信登录」按钮：`uni.login` → `POST /auth/login`；
- 手机号输入框：开发环境（后端 `WX_MOCK=true`）会顺带调
  `POST /auth/bind-phone` 绑定手机号，方便被邀请人直接看到 pending 邀请；
- 「获取验证码」如实提示「短信登录暂未开通」—— 不做一个永远收不到验证码的假倒计时；
- 登录后由 `GET /projects` 决定落点：有待确认邀请先去邀请列表，否则直接进项目列表；
  角色由管理员按手机号邀请时固定，登录流程不再经过角色选择页；
- 没有项目时展示引导页，并允许在空态直接绑定手机号：
  微信端用 `getPhoneNumber`（需要真实 AppID），H5 开发环境用手机号输入框。

## 首页（我的项目）

首页使用 `navigationStyle: custom`，顶部是品牌渐变区，下面是搜索、状态筛选与项目卡片。
数据全部来自 `GET /projects`：

- 项目卡片展示名称、地址、业主 / 主工长、总进度、状态与 3 个阶段胶囊；
- 业主 / 主工长由后端 `ownerName` / `foremanName` 返回，昵称为空时回落到脱敏手机号；
- 阶段胶囊取「当前阶段起连续 3 个」，全部结清时取最后 3 个；
- 搜索与筛选（范围 / 状态 / 角色 / 租户）都是前端在已拉取的列表上完成，不分页；
- 设计稿里的「已暂停」在本系统没有对应状态，按后端的 `archived` 显示为「已归档」；
- 项目新建只对租户管理员开放：C 端项目列表**不展示**「新建项目」FAB；
  管理员从项目列表顶部「管理」进入 `pages/admin/projects/index` 使用管理端 FAB 新建；
- 底部导航使用 `pages.json` 的**原生 tabBar**（项目 / 验收 / 记账 / 我的）。
  四项均已成为真实页面；「我的」是个人工作台，消息未读数通过
  `uni.setTabBarBadge({ index: 3 })` 显示在「我的」tab 上。

## 项目详情页

`pages/project/index` 对应 Stitch 的「阳光花园项目进度总览 - 1:1还原版」，从首页项目卡片进入：

- 项目概览：封面、状态、当前角色、总进度、地址与导航、当前阶段、计划日期与延期；
- 待我处理：业主待签字的验收单、待确认的付款节点；验收签字/付款确认直接在本页发起或跳转；
- 阶段进度：已完成、当前、下一阶段；当前阶段展开工序与完成度，可查看工序历史；
  锁定阶段直接显示「上一阶段「X」未结清」；
- 工程动态：最近一条汇报、作者与角色、完成度变化、文字、最多 4 张照片（+N）、评论数；
- 账目概览：合同总额、已收款、已支出、当前余额、下一付款节点；
- 门锁密码：业主管理、工长 / 监理查看明文，进入 `pages/project/door-code`；
  该入口对三种项目角色可见，项目归档后显示不可查看；
- 联系与导航：主工长/监理电话一键拨打、项目地址导航。

权限是页面级降级的：业主可以看联系方式、确认付款；工长可以看账目但不能确认付款；
监理看不到项目账目与联系方式。照片与账目始终来自真实接口，没有数据时显示空态。

## 门锁密码页

`pages/project/door-code` 对应 §4.8。页面进入即调用 `GET /projects/:id/door-codes`，
后端会对每条被读取的密码写 `door_code.read` 审计日志，因此**只有真正进入该页才读取**，
项目详情页不预先拉取密码，也不在本地缓存。

- 业主：新增、修改、失效密码，查看访问记录；
- 工长 / 监理：直接查看明文密码，没有管理入口；
- 条目展示名称、密码、备注、设置时间；失效只影响系统内可见性，
  弹窗会明确提示「不会改变实体锁密码，已泄露应同步换锁」；
- 项目归档后接口返回 403，页面显示不可查看；非项目成员统一 404。`

## 工程动态页

`pages/project/feed` 对应 Stitch 的「工程动态进度汇报 - 1:1还原版」，从项目详情
「工程动态 → 全部」进入：

- 顶部汇总：项目封面、最近汇报时间、近 7 天动态数、当前阶段；
- 分类筛选：全部、当前阶段、下一阶段、仅看图片、最近 7 天；
- 动态卡片：作者与角色、阶段·工序、完成度变化、正文、最多 3 张图片/视频、评论数；
- 图片支持大图预览，视频显示播放键与时长；评论可在底部面板直接发送；
- 监理填写的巡检类汇报渲染成浅橙通知卡片（仅当 `author.role === 'supervisor'`）；
  后端没有巡检/签到记录接口时，不要凭空造巡检卡片；
- 底部固定「联系工长」，取业主可见的联系方式并拨号；**工长本人查看时隐藏**
  （缺少联系方式时仍在点击后提示，不伪造号码）；
- 支持下拉刷新与触底加载。

## 考察计划与路线规划

入口在「我的」页的考察计划横幅，以及项目详情右上角「更多 → 考察计划」；
只对**工长 / 监理**显示。页面不是 tab 页，不占底部导航：

- `pages/route-plan/index`：已保存的考察计划列表，显示工地数、总里程、耗时与
  「需重新规划」标记；支持下拉刷新与分页。
- `pages/route-plan/plan`：多选自己名下的工地（搜索、最多 `route_max_points` 个，
  默认 10）；起点可用 `uni.getLocation({ type: 'gcj02' })` 获取当前位置，
  或用 `uni.chooseLocation` 手动选点。生成后展示地图折线、总里程、分段耗时与顺序列表，
  可上下调整顺序，调整后以 `optimize:false` 重新请求，不重新跑排序算法。
  「一键导航」会重新调用 preview（`optimize:true`）按最近路线排序并直接打开第一站。
- `pages/route-plan/detail`：已保存计划的详情、逐站导航、一键导航、重新规划与删除；
  项目坐标变更后后端返回 `stale: true`，页面隐藏旧折线并提示重新规划。
  一键导航会用保存的起点与项目重新规划最近路线；微信 `uni.openLocation`
  一次只能导航一个目的地，返回小程序后由 `onShow` 询问是否继续下一站。

所有坐标统一 **GCJ-02**；路线、缓存与地图 Key 都在后端，小程序只拿坐标、折线和里程。
未配置 `AMAP_KEY` 或高德不可用时，后端返回 `degraded: true`，页面显示「简化模式」，
按选择顺序逐点导航，不显示编造的里程与耗时。H5 没有地图 Key 时显示列表与说明，
微信小程序使用原生 `<map>`。

## 记账页（业主 / 工长）

`pages/ledger/index` 对应 Stitch 的「工程宝阳光花园项目记账页面 - 1:1还原版」，
是记账 tab 的首屏：

- 顶部项目名可切换项目，只列出当前账号是业主或工长的项目；没有项目上下文时
  显示项目选择列表，**不会默认取第一个项目**；
- 「我是业主」是只读角色标识，点击只解释角色来源，不能切换身份；
- 合同总览：合同总额、已支付 / 已收款、工程结余、待支付 / 待收、施工支出，
  金额全部来自 `GET /projects/:id/ledger/summary`；
- 待我处理：业主待确认的付款节点 + 待确认对账单；工长只看到有异议的对账单；
- 概览页签：付款节点时间线、本阶段账目、支出构成；
- 流水页签：收入 / 支出筛选、分页、票据缩略图与大图预览、锁定与红冲标记；
- 对账页签：对账周期、收入 / 支出、状态、提交人；点开可看明细，
  业主可确认对账或逐条提异议，确认后流水锁定；
- 业主可确认付款（`paid → confirmed`），工长看到「待业主确认」；
- 工长在「流水」页签可登记收入 / 支出（归属阶段必填，收入必须关联已解锁付款节点，
  登记收入后节点变为待业主确认）；票据当前支持 1 张；
- 工长在「对账」页签可发起周期对账；周期内必须有流水，同一周期不能重复发起；
- 监理进入记账页显示「监理不参与记账」，不会请求账目接口；
- 「查看合同」打开合同信息面板。系统没有合同附件接口，不伪造合同预览；
- 支出构成按后端真实分类计算；没有数据时显示空态，不使用设计稿里的示例百分比。

原始设计稿与渲染截图保存在 `design-refs/ledger/`。

## 我的（个人中心）

`pages/mine/index` 对应 Stitch 的「工程宝小程序 - 我的页面（橙色版）」，
按品牌主色重新调色后 1:1 还原。头部橙色渐变铺满顶部与左右两侧，
叠加白色半透明建筑线框；橙色块本身用 `mine-hero-bg.png` 收成一条**贯通页面**的
向下弧线，并在资料卡中部收口，卡片下沿延伸到橙色块之外；
建筑线框由 `scripts/gen-assets.js` 生成 `mine-hero-arch.png`。数据全部来自真实接口：

- 资料 / 账号固定角色：`GET /auth/profile?projectId=...`，返回 `accountRole`；
- 当前项目：项目列表点击项目、记账页下拉切换、或「我的」页切换条都会写入
  `gc_current_project`；切换条第一项是「全部项目」，**默认就是全部项目**；
- 业主联系人：`GET /projects/:id/contacts`，只有业主且已选中项目时展示；
- 工长统计：有当前项目时走 `GET /projects/:id/my-stats`；选择「全部项目」时走
  `GET /projects/my-stats`，汇总全部 active 项目；
- 消息未读数：`GET /notifications/unread-count`，同时刷新「我的」tab 红点；
- 工长 / 监理额外显示「考察计划」横幅，进入 `pages/route-plan/index`；
- 服务入口：订阅消息状态、意见反馈、关于我们 / 用户协议 / 隐私政策、注销账号；
  内容页会带当前项目 `tenantId`，后端按「租户已发布 → 平台基础版本」回退，
  登录前没有项目上下文时读平台版本。

角色与无项目状态：

- 业主显示「主工长 / 监理」联系卡；
- 工长显示三项汇报统计；
- 监理不显示这两块；
- 有多个项目但未选择时，显示「请选择一个项目」，**不默认取第一个项目**；
- 没有项目时显示加入项目与绑定手机号的引导。

消息中心 `pages/message/index` 使用 `GET /notifications`，支持分类、分页、单条已读、
全部已读，并按 `refType/refId` 跳转验收 / 动态 / 记账 / 项目。订阅页使用
`GET /notifications/subscriptions`，后端返回 `templateId` 后可通过
`uni.requestSubscribeMessage` 重新授权。意见反馈当前只提交文字，图片需要先补多文件暂存。

## 管理端（租户管理员）

管理端没有单独的 Stitch 设计稿，沿用品牌橙、卡片、底部面板与 `dp()` 令牌。
它不是第四种项目角色，而是后台 `admin_user` 的 `owner` / `admin` 账号在微信里的入口：

- **登录**：`pages/admin/login/index`。支持租户标识 + 用户名 + 密码 + 图形验证码
  （固定 `portal=tenant`），也支持已绑定微信的免密身份列表。验证码用 PNG data URI，
  网页后台仍返回 SVG。
- **首次入口**：小程序登录页底部新增「管理员登录」，租户管理员从这里进入管理端；
  项目列表顶部「管理」只对已登录管理员或有有效绑定的用户显示。
- **微信绑定**：`admin_wechat_binding` 以 openid 为权威键；绑定后可用当前微信免密进入。
  改密、重置、禁用、C 端注销都会自动撤销；解绑在「管理账号」页。
- **会话隔离**：管理员 token 存在 `gc_admin_*`，与 C 端 `gc_token` 分离；
  管理员 401 只回管理员登录页，不会清掉业主/工长的登录态。
- **项目**：`pages/admin/projects/index`（搜索 / 状态筛选 / 分页 / 新建）、
  `project/form`（新建/编辑、模板选择）、`project/detail`（状态流转、归档、删除、
  成员/付款节点/阶段工序入口）。
- **成员**：按手机号邀请、设主工长、移除；角色由账号固定，不提供角色替换；主工长需先改指才能移除。
- **付款节点**：查看、整表替换编辑、手工解锁；已被流水引用时如实显示 409。
- **阶段工序**：阶段/工序增删改；完成度只读，仍由 C 端进度汇报写入。
- **权限**：owner 看全租户并可删除/恢复归档；admin 只看自己创建或被授权的项目，
  隐藏 owner-only 操作。前端隐藏只是 UX，后端 `projectAccess` / `dataScope` 仍是最终校验。
- **首期不做**：账号管理、模板编辑器、系统配置、内容页、反馈、操作/登录日志、导出；
  这些仍在网页后台，数据同一套，修改实时同步。

原始设计稿与渲染截图保存在 `design-refs/ledger/`；管理端验收截图以 `admin-*.png` 命名。

## 验收页（跨项目收件箱）

验收 tab 的第一视图是**跨项目收件箱**，不是项目选择器：

- 顶部四个分类：全部项目 / 待我处理 / 进行中 / 已完成；
- 每张卡片带项目名、阶段名、主工长、地址、进度、轮次与等待时长；
- 项目名只作为卡片归属信息，不进入分类行；项目筛选放在右上角「筛选」面板里；
- 「查看阶段」打开该项目的阶段梯子（底部面板）；
- 主工长的「可发起验收」阶段也出现在「待我处理」，点击「发起验收」填写说明、
  可选现场照片后创建草稿并进入详情；
- 验收 tab 不依赖当前项目上下文；点进具体验收单时才设置 `gc_current_project`。

## 验收详情页

- 项目概览 + 五步流程（自检 / 监理审核 / 业主签名 / 验收通过 / 阶段结算）；
- 无监理项目自动把「监理审核」显示为「已跳过」；
- 门禁提示明确区分「验收通过解锁付款节点」与「结算后解锁下一阶段」；
- 四个内容 tab：验收项 / 现场照片 / 流转记录 / 验收报告；
- 主工长可逐项勾选合格 / 不合格，提交自检或保存草稿；
- 监理可「通过 / 驳回」；业主可「通过并签名 / 驳回」；
- 业主签名用 canvas 手写，签名图通过 multipart `signature` 字段一次性提交；
- 驳回原因必填，可附一张凭证照片；
- 报告生成失败可重试，不阻断验收结果。

## 进度汇报附件上传（后端已就绪）

微信小程序的 `uni.uploadFile` 一次只能带一个文件，而汇报提交要求「附件 + 完成度
+ 汇报记录」一次原子写入。因此后端拆成两步，前端不要试图在一次请求里带齐 9 图 + 1 视频：

1. 逐文件 `POST /projects/:id/reports/media`（multipart，字段名任意，建议 `files`），
   表单带 `itemId`；视频额外带 `duration`。响应返回 `mediaId`、带水印的 `url`；
2. 提交 `POST /projects/:id/reports`，带 `itemId / progress / content /
   clientRequestId / mediaIds`；`mediaIds` 是上一步返回的 ID 数组。

注意：

- `mediaIds` 与直接 `files` 两种方式互斥；同一次提交只能选一种。
- 暂存附件绑定「上传人 + 项目 + 工序」，不能被其他账号或其他工序消费；已提交的
  附件不能重复使用。
- 未提交的暂存附件 24 小时后由后端清理，前端换图/取消时不必等清理。
- 提交成功后 `clientRequestId` 才更换；失败重试必须复用同一个，否则会产生重复汇报。

## 底部导航

底部四项使用 `pages.json` 的原生 `tabBar`，不是每个页面自己画一个：

- 原生 tabBar 是全局的，切换 tab 不会 `reLaunch` 重建页面，因此没有白屏闪烁；
- 项目 / 验收 / 记账 / 我的都是真实页面；管理端、消息、订阅、反馈与考察计划是非 tab 页面；
- 页面内的筛选、详情、签名等浮层在 H5 下会把 z-index 提到原生 tabBar 之上；
- 小程序原生 tabBar 在 webview 外，页面内的 `bottom` 定位不需要再额外加菜单高度。

## 项目上下文

登录只解决「你是谁」；「你在哪个项目里」是独立状态。用户进入项目时前端把
`{id, tenantId, name, role}` 存入 `gc_current_project`，项目内页面必须显式读取这个
上下文，**不要默认取第一个项目**。项目列表每次刷新都会校验当前项目是否仍然可见：
被移出项目、项目归档或租户停用后立即清空，并提示「上次进入的项目已不可用」。
没有上下文时项目内页面应回到项目列表，而不是带着猜出来的 id 发请求。

H5 预览使用固定开发 code `gongchengbao-h5-dev`，后端 mock 会派生出稳定 openid，
反复刷新仍是同一个账号。

## 角色说明页的语义

**角色是账号级固定的（v2.5）。** 管理员按手机号首次邀请时确定 `user.role`：
工长在所有项目里都是工长，监理在所有项目里都是监理，不能在项目间改成别的角色；
业主可以参与多个项目。`project_member.role` 只用于项目内权限判定，必须与
`user.role` 一致。

原「选择默认视角」的交互已移除，页面只作为角色职责说明，不再写入本地偏好，
也不能改变后端权限。

## 与设计稿的两处刻意差异

1. **不绘制假的 iOS 状态栏与微信胶囊。** 设计稿里的「9:41 / 信号 / 电池」
   和右上角胶囊是手机壳示意；真机上系统状态栏与微信原生胶囊已经存在。
   页面用 `padding-top: var(--status-bar-height)` 对齐安全区，导航行右侧
   预留了胶囊宽度。
2. **SVG 一律栅格化为 PNG。** 微信小程序各端对 SVG 的支持不一致，
   背景插画、天际线、图标由 `scripts/gen-assets.js` 用 sharp 生成 3x PNG。
   角色卡实景图保留原始 JPG（每张 50–80KB），左侧羽化用页面上的白色渐变
   覆盖层实现 —— 带 alpha 的大 PNG 每张近 2MB，会直接把主包顶过微信 2MB 限制。

## 资源生成

设计稿里的内联 SVG、橙色底图与图标通过脚本转成小程序静态资源：

```bash
node scripts/gen-assets.js
```

脚本复用 `../server/node_modules/sharp`，不需要额外安装依赖。
它会优先读取 `design-refs/brand-logo.png` 生成 `logo.png`；缺失时才退回内置图形。
底部四个 tab 图标来自 `design-refs/tab-icons/{project,acceptance,ledger,mine}.png`：
`*-accent.png` 保留原图的彩色 3D 质感，`*-gray.png` 用灰度 + 暖灰着色保留明暗层次；
文件名仍是 `*-accent.png`，不要改回蓝色。
